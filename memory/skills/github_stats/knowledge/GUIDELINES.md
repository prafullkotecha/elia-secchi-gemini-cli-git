# GitHub Stats Skill

## Purpose

This skill analyzes GitHub repository statistics and generates insightful reports. It demonstrates how to build a practical autonomous agent skill using GitHub's API and data.

**Example use case**: Weekly repository activity summaries, contributor insights, issue tracking reports.

## Skill Overview

This skill shows you how to:
- Gather data from external APIs (GitHub)
- Analyze and synthesize information
- Generate structured reports
- Apply quality standards to outputs

## How to Execute This Skill

### 1. Data Collection

Use GitHub CLI or API to gather repository statistics:

```bash
# Get repository overview
gh repo view --json name,description,stargazerCount,forkCount,openIssues

# Get recent activity
gh pr list --limit 10 --json number,title,author,createdAt,state
gh issue list --limit 10 --json number,title,author,createdAt,state

# Get contributor stats
gh api repos/:owner/:repo/stats/contributors
```

### 2. Analysis Guidelines

When analyzing GitHub data:

**Focus Areas:**
- Activity trends (PRs, issues, commits)
- Contributor engagement and patterns
- Issue resolution time and health
- Growth metrics (stars, forks, community)
- Notable changes or milestones

**What to Include:**
- Quantitative metrics (numbers, percentages, trends)
- Qualitative insights (patterns, notable events)
- Comparisons (week-over-week, month-over-month)
- Actionable takeaways

**What to Avoid:**
- Superficial metrics without context
- Data dumps without analysis
- Personal information about contributors
- Speculation without data backing

### 3. Report Structure

Use this structure for GitHub stats reports:

```markdown
# GitHub Stats Report: [Repository Name]
*Report Period: [Date Range]*

## Executive Summary
[2-3 sentence overview of key findings]

## Activity Metrics

### Pull Requests
- **Total PRs**: [count] ([trend] vs last period)
- **Merged**: [count]
- **Pending**: [count]
- **Notable**: [highlight significant PRs]

### Issues
- **Total Issues**: [count] ([trend] vs last period)
- **Opened**: [count]
- **Closed**: [count]
- **Resolution Time**: [average]

### Contributors
- **Active Contributors**: [count]
- **New Contributors**: [count]
- **Top Contributors**: [names and contributions]

## Growth Metrics
- **Stars**: [count] (+[new this period])
- **Forks**: [count] (+[new this period])
- **Watchers**: [count]

## Key Insights
[Bullet points of notable patterns or findings]

## Recommendations
[Optional: actionable suggestions based on the data]

---
*Generated by GitHub Stats Skill*
```

### 4. Quality Standards

**Data Accuracy:**
- ✅ Verify all numbers match actual GitHub data
- ✅ Use consistent date ranges for comparisons
- ✅ Clearly label all metrics and their meanings

**Clarity:**
- ✅ Use clear headings and structure
- ✅ Explain trends in plain language
- ✅ Highlight what's important
- ❌ Don't overwhelm with too many metrics

**Actionability:**
- ✅ Provide context for numbers
- ✅ Identify patterns and trends
- ✅ Suggest what the data means
- ❌ Don't just list statistics

**Privacy:**
- ✅ Use publicly available data only
- ✅ Aggregate contributor metrics
- ❌ Don't share sensitive information
- ❌ Don't speculate about individuals

## Output Requirements

### File Naming
Use descriptive, timestamped filenames:
- Format: `YYYY-MM-DD-stats.md`
- Example: `2025-01-15-stats.md`

### Location
Save all reports to: `memory/skills/github_stats/output/`

### Format
- Use Markdown format
- Include metadata (date, period, repository)
- Follow the structure template above
- Keep it readable and well-formatted

## When to Skip Execution

Skip report generation if:
- No significant activity in the period (e.g., < 3 events)
- GitHub API is unavailable or rate-limited
- Repository data is incomplete or inaccessible
- Previous report for same period already exists

## Example Workflow

1. **Identify target repository** (from demand file)
2. **Gather data** using GitHub CLI commands
3. **Analyze metrics** following the guidelines
4. **Generate report** using the template structure
5. **Save to output directory** with proper filename
6. **Quality check** against standards above

## Tips for Success

- Start with the most important metrics
- Use comparisons to show trends
- Keep language clear and non-technical
- Focus on insights, not just data
- Make reports skimmable (good headings, bullets)

## Common Pitfalls to Avoid

- ❌ Information overload (too many metrics)
- ❌ Missing context (numbers without meaning)
- ❌ Stale data (not checking recency)
- ❌ Inconsistent formatting
- ❌ Violating privacy (revealing sensitive info)
